# MVP 產品規格

> 本文件是 Shared Ledger 產品範圍、功能完成度、驗收條件與優先順序的唯一來源。技術實作請參考[架構說明](ARCHITECTURE.md)，上架文案請參考 [App Store 與 TestFlight](AppStore_TestFlight_zh-TW.md)。

## 產品目標

讓家庭、伴侶、室友與旅行群組能在同一個共享空間建立多個用途獨立的帳本，清楚知道每筆款項所屬帳本、來源帳戶、分類、分攤方式與最終結算結果。

## 核心使用流程

1. 建立群組並邀請成員。
2. 在群組內建立或選擇帳本，例如家庭日常、旅行或裝潢。
3. 在群組建立共用記帳帳戶與分類目錄，並為目前帳本選擇要使用的分類。
4. 使用群組帳戶在目前帳本新增收入、支出或帳戶轉帳。
5. 指定付款人、參與成員與分攤方式。
6. 查看整個群組、目前帳本或自選帳本的收支與分類統計，以及跨帳本的群組帳戶餘額。
7. 依「誰應付給誰」的建議完成全額或部分結算。
8. 離線時持續記帳，恢復連線後同步共享資料。

## 手機快速上手與生活分類

本輪手機 UI 更新以減少日常記帳步驟為主：

- 總覽提供目前帳本的「記支出／記收入」入口，明示新增日期預設為今天，不受報表月份影響；交易頁在一般字級保留底部操作區，輔助字級則移入可捲動內容。
- 第一次使用可由空畫面直接建立群組；缺少帳戶時，記帳表單可直接前往帳戶設定。表單呈現群組、帳本、貨幣與金額，數字鍵盤提供完成按鈕。
- 新群組預設帶入以「食、衣、住、行、育、樂」開頭的 18 個大類、481 個分類節點（含大類與中間層，其中 381 個末端細項，包含收入分類）。最深四層，例如「行 → 開車 → 保養費 → 機油與油品」，也能在任一層自行新增。
- 已有群組從分類頁「預覽與補入預設分類」主動套用；沿用同父層的同名分類、補入缺少的節點，保留既有改名、歷史交易及帳本停用選擇。舊分類不會被自動搬移到新分類下。
- 分類管理可展開／收合子分類；記帳先選大類再逐層進入，也可直接選用父分類。搜尋涵蓋目前帳本可用分類及上層名稱，結果顯示完整路徑；選取任一層後關閉整個選擇畫面。編輯舊交易時仍能保留原本已停用或封存的分類。分類名稱仍是建立時保存的使用者資料，不因切換語言而重新命名。

驗收包含：新群組第一筆交易、現有群組補入及重複補入、第四層分類記帳、跨帳本啟用與停用、唯讀權限、目錄搜尋保留祖先路徑、父分類及細項選取後關閉、無搜尋結果恢復、正體中文／英文、深色模式、VoiceOver 與最大 Dynamic Type。實機 UI 驗收仍待完成。

### 完整生活分類目錄

目錄兼顧學生、租屋、家庭、育兒、長輩照護、養寵物、工作與退休等生活情境。保留原有 53 個節點的名稱與父層位置，擴充 428 個節點；18 個大類之下共有 463 個子分類，深度包含大類最多四層。使用者可依習慣停用不需要的分支，也可只記在較粗的父分類。

既有群組的預覽可展開或搜尋；搜尋保留命中細項的祖先，方便辨認用途。右上角「補入完整分類」會補齊整份目錄，搜尋條件只影響預覽。重複補入不會新增同父層同名節點；已停用分支的新增子孫仍在該帳本停用。目錄不自動改寫舊交易，也不自動覆蓋使用者自訂名稱。

生活費用以用途歸類：車險在交通、住宅保險在居住、商業人身保險在醫療健康，社會保險另列。稅金與規費集中方便查找；僅提供分類名稱，不計算稅額或申報。帳戶間移轉、信用卡繳款應使用既有轉帳功能，避免同一筆消費重複列支；未將存款或投資本金新增為一般支出細項。

## P0：完整 MVP 必須補齊

下列功能直接影響帳務正確性、共享可信度或核心流程，優先於 OCR、Widget 等增強功能。這份清單定義的是 MVP 的需求範圍，不是進度；目前各項的實作狀態以上方的「功能完整度快照」為準。

1. **交易完整生命週期**：交易詳情、編輯、作廢／刪除確認與變更稽核；已參與結算的交易不得靜默改寫。
2. **完整分攤與多人付款**：平均、比例、指定金額、部分成員與多人付款；保存使用者選擇的分攤模式及輸入值，付款總額和分攤總額都必須等於交易金額，並依貨幣最小單位明確處理尾差。
3. **多帳本生命週期與資料隔離**：一個群組可建立多個帳本，並支援建立、重新命名、排序、切換、設定預設與封存；帳戶與分類主資料屬於群組，帳本透過啟用關聯決定可使用的分類，交易仍只屬於一個帳本。交易不得引用其他群組的帳戶、其他群組的分類或目前帳本未啟用的分類。
4. **真實帳戶餘額與對帳**：在群組範圍內處理期初餘額、所有帳本交易與帳戶直屬調整對餘額的正確影響、帳戶明細、對帳日期，以及有歷史時只能封存不可刪除。
5. **債務與結算引擎**：逐成員淨額、「誰應付給誰」與最少筆數建議；支援全額／部分結算、外部付款備註、結算歷史與撤銷。
6. **搜尋、篩選與核對**：依關鍵字、日期、金額、帳戶、分類、付款人、參與成員與交易類型篩選，並提供月份分組與無結果狀態。
7. **群組與成員生命週期**：邀請重送與撤回、移除／退出、擁有權轉移；建立群組時明確保存單一 ISO 4217 貨幣；接受共享後需確認目前 Apple Account 對應的 App 成員，對應只保存在 private store；成員離開後保留顯示名稱快照，不破壞歷史帳務。
8. **角色權限真正生效**：擁有者、管理員、成員、唯讀成員的檢視、記帳、帳本管理、設定、邀請、結算與刪除權限必須一致生效。
9. **可用的總覽與跨帳本月報表**：本月收入／支出、收支淨額、分類占比、各帳本占比與月份切換使用真實資料；支援整個群組、目前帳本與自選帳本範圍。帳戶餘額使用群組內所有帳本交易與帳戶調整；成員淨額與結算仍以單一帳本為帳務邊界，所有畫面必須明確標示範圍。
10. **同步狀態與錯誤恢復**：呈現未登入、同步中、成功、離線、失敗與重試狀態，並完成雙帳號、離線恢復與衝突測試。
11. **資料可攜與刪除**：支援完整 CSV 匯出與系統分享；可刪除本機群組／個人資料，並清楚說明共享資料影響。
12. **通知與提醒最低版本**：群組邀請、交易修改與待結算通知可個別關閉；未授權通知時仍能正常使用 App。
13. **品質與可及性門檻**：完成核心計算、資料整合與關鍵流程測試；驗證 Dynamic Type、VoiceOver、深色模式、減少動態效果與金額格式。介面文案以正體中文為準；已進 String Catalog 的畫面兩種語言都要一起驗。

### P0-2 分攤與多人付款實作範圍與剩餘項目

- 新增穩定的分攤模式：`equal`、`percentage`、`fixedAmount`；既有交易缺少模式時視為 `equal`，不得改變目前保存的 `EntrySplit.amount`。
- `EntrySplit.amount` 保存每位成員最後實際負擔金額；另保存比例或指定金額的原始輸入快照，讓交易詳情、編輯與稽核能還原使用者當時的設定。
- 平均分攤允許只選部分成員；比例分攤要求每位比例大於零且合計精確等於 100%；指定金額要求每筆非負且合計等於交易金額。
- 將目前單一 `LedgerEntry.payer` 擴充為付款明細，支援一位或多位付款人及各自付款金額；付款總額必須等於交易金額。
- 尾差依交易貨幣的最小單位計算，不得固定假設兩位小數；採可重現的分配順序，最終付款與分攤總額都必須精確等於交易金額。
- 新增交易已使用同一套 Domain／repository 驗證；後續交易編輯必須重用相同 API。無效比例、無效指定金額、重複付款人、跨群組成員及封存成員都必須被資料層拒絕。
- 交易修改或作廢後重新計算成員淨額與結算結果，並保存修改前後的付款及分攤快照，不可靜默覆寫歷史。
- 單元測試涵蓋平均、比例、指定金額、部分成員、多人付款、零位與三位小數貨幣、正負尾差及無效輸入；交易編輯測試隨完整生命週期功能補上。

### P0-3 群組分類與帳本啟用規則

- 分類主資料與完整父子樹屬於群組；同群組帳本引用同一個分類識別，不為每本帳本複製同名分類。
- 「群組設定 → 分類管理」負責新增、重新命名、排序、合併與封存；群組層級的名稱或階層修改會反映到所有使用該分類的帳本，執行前需清楚提示影響範圍。
- 「帳本設定 → 使用的分類」只管理目前帳本的啟用、隱藏與顯示順序。停用分類不會刪除分類，也不影響既有交易、報表或稽核紀錄。
- 從群組分類管理新增的分類預設啟用於所有啟用中的帳本；若從帳本情境提供新增捷徑，預設只在目前帳本啟用，並可由使用者改為套用其他帳本。
- 建立新帳本時可使用群組預設分類、沿用另一帳本的啟用設定或空白開始；預設採群組預設分類，避免重複設定。
- 交易建立或修改時只能選擇同群組且目前帳本已啟用、未封存的分類；停用或封存後，歷史交易仍顯示當時分類。
- 封存分類是群組層級操作；父分類仍有啟用中的子分類或分類仍被歷史交易引用時，必須提供安全規則與影響說明，不可造成無法存取的孤兒分類。
- 不同群組的分類資料彼此隔離；跨群組重用透過未來的個人分類範本處理，不直接共享會持續同步的分類物件。
- 群組分類管理與帳本分類啟用必須遵守角色權限；唯讀成員只能查看與使用，不可變更設定。

### P0-9 群組跨帳本統計

- 群組總覽預設統計所有啟用中的帳本，並可切換為目前帳本或自選同群組帳本；不得跨群組合併資料。
- 基本統計包含期間收入、支出、收支淨額、群組共用分類占比，以及各帳本對群組收入與支出的貢獻；轉帳與帳戶餘額調整不列入收入／支出。
- 分類彙總使用群組分類的穩定識別，不依分類名稱自動合併。V4 群組共用分類與 assignment 修復完成前，不得以同名文字假設為同一分類。
- 群組帳戶餘額維持整個群組範圍，包含所有帳本交易與帳戶調整，並與期間收支分開呈現，避免將資產餘額與現金流混為一談。
- 成員淨額、債務與結算在 MVP 仍以單一帳本計算；群組總覽可並列或加總顯示各帳本結果，但每個數字必須保留帳本歸屬，不直接建立跨帳本結算。
- 所有統計數字、分類區塊與帳本占比都能下鑽到來源交易，明細必須顯示所屬帳本、日期與目前套用的統計範圍。
- 已封存帳本預設不納入目前群組統計；使用者進入歷史範圍或明確選取時才納入，且畫面需標示包含封存資料。
- 多幣別完成前，不得直接相加不同幣別的金額；若資料無法在同一幣別下比較，必須分幣別呈現或阻止合併總額。
- P0 只要求真實總額、占比、月份切換、範圍切換與來源核對；期間比較、趨勢與進階洞察維持 P1。

### P0-12 通知與提醒實作範圍

- 通知一律由裝置自己產生。App 沒有伺服器，`NSPersistentCloudKitContainer` 的推播是靜默的，只用來觸發同步；所有提醒都是同步完成後，由本機從共享的稽核紀錄推導出來的 local notification。
- 三個種類各自獨立開關，任一種類關閉不影響其他種類：群組邀請與成員異動、交易修改（新增／編輯／作廢）、待結算提醒。偏好與遞送紀錄只存在本機 `UserDefaults`，不同步到其他成員或其他裝置。
- 未授權、被拒絕或查不到授權狀態時一則都不送，且記帳、同步、結算、匯出與刪除完全不受影響；設定頁的種類開關在未授權時仍可調整，只註明目前不會送出。
- 不在啟動時詢問通知權限；只有使用者在通知設定頁主動要求時才詢問。系統層級已拒絕時不再重複詢問，改為導向系統設定。
- 自己的操作不通知自己。稽核事件只記得下顯示名稱，因此以群組內目前成員的名稱比對。
- 第一次執行（或剛接受一個共享群組）只取基準不通知，避免整段匯入的歷史逐筆跳出；超過 24 小時的事件也不再通知，因為 CloudKit 匯入順序與事件時間無關。
- 未授權期間仍推進稽核事件的基準線，使用者之後授權時不會被補送的舊事件洗版；待結算提醒相反，關閉或未授權時不留紀錄，打開後會立刻提醒目前仍未結清的款項。
- 待結算提醒以「與目前使用者有關的建議結算筆數與方向」判斷是否重複，每個帳本同時最多一則，且兩則之間至少間隔 12 小時；款項結清後清除紀錄。
- 通知內容只說明發生了什麼事，不含金額與備註：通知會出現在鎖定畫面上。App 在前景時給橫幅與通知中心但不出聲。
- 判斷邏輯（要不要送、送幾則、何時重複）全部放在純函式，與 Core Data 及 `UNUserNotificationCenter` 分離，並以單元測試涵蓋首次執行、自身操作、過期事件、關閉種類、未授權與待結算冷卻等組合。

## MVP 驗收條件

### 群組、帳本、成員與權限

- 群組建立者自動成為擁有者。
- 建立群組時保存一個有效 ISO 4217 `currencyCode`；帳本、帳戶、交易、分攤及餘額統一沿用，輸入與尾差依該貨幣的小數位數驗證，畫面不得硬編碼 `$`。
- 每個群組建立時自動產生「主要帳本」，且任何時候至少保留一個啟用中的帳本與一個明確的預設帳本。
- 使用者可在同一群組建立及切換多個帳本；封存帳本不刪除既有帳務資料。
- 加入群組即可看見該群組全部帳戶與帳本；MVP 不提供逐帳本成員或單一本帳本分享。
- 接受 shared group 後，使用者必須確認待邀請的 member／viewer，或以基本 member 身分加入；App 將 `groupID`／`memberID` 對應只保存於目前 Apple Account 的 private store，不同步 `isCurrentUser` 旗標，也不得以姓名自動猜測或直接認領 owner／administrator。
- 擁有者、管理員、成員與唯讀四種角色的權限符合 P0 定義。
- 已撤回或失效的邀請不可加入；移除或離開的成員不破壞歷史帳務。
- 使用兩個不同 Apple Account 完成邀請、接受、編輯與同步驗證。

### 帳戶、分類、交易與結算

- 帳戶與分類主資料明確歸屬群組，並可被同群組的多個帳本共用；交易明確歸屬單一帳本，帳本以啟用關聯決定可用分類。跨群組帳戶、跨群組分類或使用目前帳本未啟用分類的交易會被資料層拒絕。
- 帳戶餘額能由期初餘額、群組內所有帳本的相關交易與帳戶直屬調整正確推導；同群組帳戶間的轉帳不改變群組總資產，且不列入收入／支出。
- 一般交易一定屬於單一帳本；餘額調整直接屬於帳戶並保留原因與時間，不以無帳本交易表示。
- 分類在群組內形成唯一階層，帳本可啟用或停用其中的分類；停用不影響歷史，已被交易使用的分類只能封存，不能直接刪除。
- 收入、支出與同帳本轉帳都能新增、核對、編輯或作廢；平均、比例與指定金額分攤皆可選部分成員並在詳情完整還原原始設定。
- 單人或多人付款的付款明細合計、分攤明細合計與交易金額三者一致；任何不一致都無法保存。
- 系統能正確產生成員淨額及結算建議，並保存部分／完整結算歷史。
- 金額計算精確，任何付款、分攤或結算都不產生無法解釋的尾差。

| 畫面或計算 | 預設資料範圍 |
| --- | --- |
| 帳戶餘額與帳戶明細 | 整個群組，包含所有帳本交易與帳戶調整；明細標示交易所屬帳本 |
| 收入、支出與分類報表 | 群組總覽預設所有啟用帳本，並可切換目前帳本或自選帳本；分類使用群組共用識別，轉帳與餘額調整不列入收入／支出 |
| 成員淨額與結算 | 目前帳本；群組總覽只能彙總並清楚標示各帳本結果 |
| 交易搜尋與匯出 | 預設目前帳本；若提供跨帳本模式，必須明確標示範圍 |

### 報表、資料與同步

- 總覽、報表、搜尋與匯出均來自真實資料，結果能回到原始交易核對。
- 群組跨帳本報表能在整個群組、目前帳本與自選帳本之間切換；收入、支出、分類及帳本占比正確，且下鑽明細保留來源帳本。
- 帳戶餘額、期間收支與成員結算清楚標示不同計算範圍；封存帳本與不同幣別不會被靜默納入或錯誤相加。
- 無網路時仍可新增與瀏覽本機資料，恢復網路後能同步。
- 未登入 iCloud、同步失敗與資料衝突都有清楚且可恢復的使用者體驗。
- V1／V2／V3／V4 舊資料升級後，帳戶保留在原群組並可供各帳本共用；既有分類提升為群組分類，並保留原帳本的啟用關聯，不依名稱自動合併；交易仍歸入原帳本或所屬群組的「主要帳本」，舊版餘額調整轉成帳戶直屬紀錄。V5 移除會同步的 `Member.isCurrentUser`，共享群組在缺少 private identity mapping 時要求重新確認身分；V6 以 `TWD` schema 預設回填既有群組的 `currencyCode`；V7 將舊單一 `payer` 冪等轉成一筆全額 `EntryPayment`，既有 split amount 保持不變並以 `equal` 作為預設模式；V8 在共享 `Member` 新增 optional `cloudParticipantID`，既有成員升級後維持 `nil`，不做猜測式回填，等到在有效 CKShare 上認領或加入時才綁定。餘額及歷史關聯保持一致，重複執行修復不產生重複資料。
- 刪除、匯出與共享資料影響有明確說明及確認步驟。
- 群組邀請與成員異動、交易修改、待結算三類通知可個別關閉且互不影響；拒絕或未開啟通知權限時 App 所有功能仍完整可用，也不會出現要求授權才能繼續的流程。

## P1：MVP 穩定後的高價值功能

- 重複交易、到期提醒與單次例外處理。
- 群組／分類預算、超支提醒與月結轉規則。
- 收據照片、附件、商家、標籤與保固備註。
- 多幣別、基準幣別、匯率日期、手動覆寫與結算匯率快照。
- 期間比較、趨勢、成員與分類分析，以及可回溯原始交易的洞察。
- 版本化 CSV 匯入、預覽驗證、重複偵測與失敗回滾。
- Face ID／Touch ID App Lock、背景遮罩與敏感通知選項。
- 常用交易範本、複製上一筆、內建計算機與最近選項。
- 每本帳本可釘選或隱藏常用群組帳戶；這只影響選單，不改變帳戶所有權與歷史資料。
- 個人分類範本可在建立新群組時套用；套用時建立該群組自己的分類資料，不讓不同群組共享持續同步的分類物件。
- **多語系與在地化**：首波支援正體中文與英文，完整處理幣別、日期、時區、數字、複數與無障礙文案；詳細範圍與驗收條件如下。

### 多語系與在地化

> 基礎建設已完成，實作細節與遷移進度見[多語系與在地化](LOCALIZATION.md)。String Catalog、鍵註冊表、可指定語言的查詢層、日期與百分比格式化，以及守住漏翻與參數不一致的測試都已就位；分頁、設定頁、iCloud 同步、通知與跨畫面共用的列舉已遷移，其餘畫面仍是硬編碼的正體中文字串。

- 首波支援正體中文（`zh-Hant`）與英文（`en`），預設依 iOS 系統語言顯示；架構需允許後續新增語言。
- 使用 Xcode String Catalog（`.xcstrings`）集中管理所有使用者可見文字，包括 SwiftUI 畫面、錯誤訊息、通知與 VoiceOver 標籤，不在程式碼中硬編碼顯示字串。
- 日期、時間、數字、百分比與金額依目前 `Locale` 顯示；貨幣格式以帳本、帳戶或交易保存的貨幣代碼為準，不只依裝置地區推測。
- 複數、語序與帶參數訊息使用 String Catalog 的變化規則，不以字串串接組成句子。
- 使用者自訂的群組、帳本、帳戶與分類名稱保留原文；App 內建的預設分類使用穩定識別碼對應各語言名稱，切換語言不得改變資料關聯。
- 新增功能時，同一個 PR 必須補齊正體中文與英文文案，並檢查長字串、Dynamic Type、VoiceOver 與不同螢幕尺寸的版面。
- 驗收時須確認兩種語言的核心流程沒有未翻譯 key，日期、金額及複數格式正確，切換語言後既有帳務資料保持不變。

- OCR 收據辨識與使用者確認流程。
- Widget、App Intents／Shortcuts、Spotlight 與 Siri 快速記帳。
- Apple Watch 快速新增與查看待結算。
- 智慧分類、重複交易偵測與可解釋、可取消的自然語言建議。

## P3：Apple Intelligence 與進階智慧功能

P3 建立在 P2 的 App Intents、Spotlight、OCR 與完整帳務規則之上。實作時以 Apple 當期的 [Foundation Models](https://developer.apple.com/documentation/foundationmodels) 與 [App Intents](https://developer.apple.com/documentation/appintents) 官方介面為準，不提前提高目前 iOS 17 核心功能的最低需求。

### 待加入功能

- 自然語言建立交易草稿，例如從「昨天晚餐 1,200 元，小明先付，我和小美各一半」產生日期、金額、帳戶、分類、付款與分攤候選值。
- 依目前群組與帳本資料提出分類、帳戶、分攤成員與重複交易建議，並解釋建議依據。
- 以自然語言查詢帳務，例如「這個月餐飲比上個月多多少」，答案可回到實際交易與報表核對。
- 產生期間摘要、異常支出提示與可執行的整理建議；不得把推測描述成已確認事實。
- 透過 App Intents／Siri AI 查詢帳本或建立草稿；正式儲存、結算、刪除、邀請與共享仍遵守 App 內相同權限及確認流程。

### 安全、隱私與帳務規則

- Apple Intelligence 只提供理解、建議與草稿；金額、分攤、餘額、債務、結算、權限及 migration 一律由可測試的 Domain／repository 規則決定，模型輸出不是帳務真實來源。
- 模型不得直接新增、修改、作廢或刪除帳務資料。所有會改變資料的結果先以結構化預覽呈現，經使用者確認並通過 repository 驗證後才可寫入。
- 使用 Foundation Models 的 guided generation／結構化輸出限制欄位型別與選項；模型產生的 UUID、金額、日期、帳戶、分類、成員及比例仍須重新查找並驗證，不可信任純文字輸出。
- 只提供完成當次請求所需的最小資料，且不得超出目前使用者可存取的群組與帳本 scope；角色權限、封存狀態及跨群組限制在 App 端強制執行，不能交由 prompt 約束。
- 群組名稱、交易備註、OCR 文字與附件內容視為不可信資料，不得被當成系統指令或繞過工具／repository 權限。
- 優先使用 Apple 系統提供的模型能力。若未來啟用 Private Cloud Compute、其他模型 provider 或第三方服務，必須在傳送前清楚揭露資料範圍、取得同意，並重新檢查隱私政策、App Privacy 與共享成員影響。
- 不以群組帳務、提示內容或模型回覆訓練自有或第三方模型；除非使用者主動提交診斷，不保存完整 prompt、回覆或 Foundation Models session transcript。
- AI 產生的草稿與洞察需標示為建議，顯示所用帳本、日期範圍與來源交易；無法由真實資料核對的數字不得顯示為確定金額。

### 可用性、降級與驗收

- 每次使用前檢查系統模型的 runtime availability，涵蓋不支援的裝置、Apple Intelligence 未啟用、模型尚未就緒及語言不可用；不可只以 OS 版本或機型推測。
- Apple Intelligence 不可用、逾時或生成失敗時，核心記帳、搜尋、報表、匯出與結算仍完整可用，並提供手動輸入或既有規則式功能，不出現無法離開的 loading 狀態。
- App Intents 與模型工具只能呼叫正式 Domain／repository API，不建立第二套帳務邏輯；需要確認的操作在 Siri、Shortcuts 與 App 內維持一致。
- 評估至少涵蓋正體中文與英文、不同日期／幣別格式、比例與指定金額分攤、模糊敘述、惡意備註、跨群組請求、封存資料、無模型與中斷恢復。
- 數字正確性以固定資料集驗證：模型可以選擇查詢或摘要方式，但所有總額、差額、比例與結算結果必須由 deterministic calculator 產生並能回溯來源。
- P3 功能完成需包含真實支援裝置驗證、Dynamic Type、VoiceOver、錯誤與降級狀態、效能／耗電觀察，以及使用者可取消生成與清除 AI 暫存資料。

## 功能完成定義

功能只有在資料模型與遷移、正確的群組／帳本 scope、權限、離線與同步、錯誤狀態、可及性、測試及真實資料畫面都完成後，才可標記完成。只有畫面入口、靜態卡片、資料欄位或 happy path 不算完成。
